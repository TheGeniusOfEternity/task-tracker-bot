# Task Tracker Bot

Telegram-бот для совместного управления задачами. TypeScript, grammY, PostgreSQL / Neon и Vercel Functions. Все взаимодействия происходят в личных сообщениях с ботом.

Подходит для команды, проекта, клуба или бытовых дел. Группа — внутреннее объединение участников в боте; общий Telegram-чат не требуется.

## Что умеет MVP

- Администратор создаёт группу и получает одну ссылку-приглашение с кнопкой «Присоединиться». Её можно переслать: ссылка откроет нужного бота и передаст код через Start. Ссылка действует 7 дней; новая отменяет предыдущую.
- Участники вступают по ссылке; ручная команда `/join КОД` также поддерживается. Один пользователь состоит в одной группе у каждого бота; у разных ботов группы независимы.
- Несколько ботов для разных направлений работают в одном проекте Vercel и одной базе Neon. Их участники, задачи, личные имена, диалоги, журналы и уведомления разделены.
- «Группа» показывает участников, их открытые задачи и кнопку «Назвать для себя». Например, «Елена Иванова» → «Координатор». Личные имена видны только тому, кто их настроил. Можно вернуть имя из Telegram.
- Администратор создаёт разовые, ежедневные, еженедельные и ежемесячные задачи с постоянным исполнителем. Для месячного повтора выбираются первые, вторые, третьи, четвёртые или последние вхождения отмеченных дней недели.
- При создании задачи расписание выбирается так: сначала дни недели inline-отметками и «Готово», затем «Без повтора», «Еженедельно» или «Ежемесячно». Отметки обновляются в том же сообщении; все семь дней отображаются как «Каждый день».
- Исполнитель отмечает выполнение inline-кнопкой и может отменить свою отметку.
- Исполнитель просит помощи у одного или нескольких участников. Первый согласившийся получает текущее повторение задачи целиком; просьба для остальных закрывается. Будущие повторения остаются у постоянного исполнителя.
- Личные напоминания о задачах на сегодня и просроченных с выбранным режимом просрочки; журнал событий за последние 7 дней, до 20 записей.

Бот не получает адресную книгу Telegram. Личные имена задаются вручную через список группы. Любой участник группы может просматривать задачи других; завершать задачу может только её текущий исполнитель.

Вся навигация находится в сообщениях бота: «Мои задачи», «Группа», «Журнал», создание задачи и приглашение для администратора. Нажатия inline-кнопок не создают пользовательских сообщений. У текстовых шагов есть кнопка возврата в меню, отменяющая текущий диалог. Повторное открытие приглашения уже вступившим участником и ошибки текстового ввода также показывают inline-кнопки продолжения. При первом открытии меню бот убирает клавиатуру под полем ввода, оставшуюся от предыдущей версии.

При переходах по меню и шагам диалога предыдущий экран бота удаляется только после успешной доставки нового. Журнал листается кнопками на одном экране. Напоминания, назначения задач и адресованные просьбы о помощи сохраняются отдельно. Очистка относится к сообщениям бота, а не пользовательскому вводу. Telegram позволяет удалять такие сообщения не старше 48 часов; прежняя история, идентификаторы которой бот не сохранял, может остаться. Ошибка удаления старого сообщения не мешает работе нового экрана.

## Правила расписания

Часовой пояс первой версии — `Europe/Moscow`. Срок задачи — конец указанного дня. При создании задачи:

1. Выберите один или несколько дней недели, затем нажмите «Готово». Кнопка «Каждый день» отмечает все дни; повторное нажатие снимает все отметки. Нельзя продолжить с пустым выбором.
2. Выберите периодичность: «Без повтора», «Еженедельно» или «Ежемесячно». Для месяца дополнительно уточните, какие вхождения нужны — первые, вторые, третьи, четвёртые или последние выбранные дни. Например, понедельник и суббота + ежемесячно + первые создают сроки на первый понедельник и первую субботу каждого месяца.

После выбора периодичности сразу появляется сводка с автоматически рассчитанным первым сроком и кнопками «Назад», «Отмена», «Создать». На каждом предыдущем экране есть «Назад» и «Отмена»; при вводе названия — только «Отмена». На экране периодичности доступны только варианты повтора и навигация. Ручная дата задаётся из сводки кнопкой «📅 Изменить дату»: введите дату в формате ГГГГ-ММ-ДД или нажмите «⬅️ Назад», чтобы вернуться без изменений. По умолчанию при просрочке действуют напоминания по выходным без копий открытой задачи. Все дни + еженедельно означают ежедневную задачу. Все дни + ежемесячно + первые означают ежедневные сроки 1–7 числа каждого месяца; последние — последние семь дней месяца.

Для разовой задачи срок — ближайший выбранный день недели строго после сегодня (сегодняшний день пропускается). Для повторяющейся задачи расписание действует с сегодня: сроки за прошедшие дни не создаются, выбранный сегодняшний день может стать первым сроком. Необязательная ручная дата задаёт точный срок разовой задачи или нижнюю границу повторяющегося расписания. Дни в кнопках и подписях сокращены: Пн, Вт, Ср, Чт, Пт, Сб, Вс. Кнопки перехода и возврата расположены в одной строке. Все кнопки снабжены тематическими эмодзи. Статусы в списке и карточке задачи обозначены кружками: 🔵 предстоит, 🟡 на сегодня, 🔴 просрочено, 🟢 выполнено. Карточка показывает «Попросить помощи» либо «Отменить просьбу о помощи» в зависимости от наличия открытой просьбы. Старые сохранённые расписания продолжают работать, включая:

- **По числу:** число даты начала, в коротком месяце — последний день.
- **По дню недели:** например, первая суббота или последний вторник каждого месяца. Дата начала задаёт нижнюю границу расписания: если выбранный день этого месяца уже прошёл, первый срок будет в следующем месяце.

При создании выбирается режим просрочки:

| Режим | Напоминания и повторения |
| --- | --- |
| Каждый день, отдельно | Ежедневные напоминания; каждый календарный срок — отдельная задача. Просроченные повторения накапливаются. Будущие создаются на 7 дней вперёд. |
| По выходным, без копий | Напоминание в исходный день срока, затем по субботам и воскресеньям. Одна открытая задача сохраняет исходный срок, исполнителя и историю. Новые календарные даты не создают дубликатов, пока она открыта. |

Пример: задача на первую субботу месяца открылась **7 ноября 2026**. Если её не выполнить, бот напомнит **8, 14, 15 ноября** и далее по выходным. **5 декабря** новая копия не появится. Если выполнить **6 декабря**, следующий срок будет **2 января 2027**. Завершение закрывает накопившуюся потребность, включая календарные сроки до дня выполнения; расписание продолжает отсчитываться по календарю, а не от фактической даты выполнения.

В режиме без копий открытая задача видна в списке и в будни; меняются дни напоминаний. После завершения следующие повторения открываются в свой календарный день, а не заранее. Первое повторение всегда видно сразу после создания, даже если срок далеко в будущем. Отменить отметку можно, пока не открылся следующий цикл. Разовая задача после завершения не возобновляется.

Задачи из предыдущих версий сохраняют прежний режим — ежедневные напоминания и отдельный учёт повторений.

Напоминания настроены на 16:00 UTC, то есть в интервале 19:00–20:00 по Москве на Vercel Hobby. Точная минута не гарантируется. Для изменения времени обновите `crons` в `vercel.json` и выполните повторный деплой.

Функции закреплены в `iad1` (Вашингтон), рядом с текущей базой Neon в `aws-us-east-1`. При переносе базы обновите `regions` в `vercel.json`, чтобы не добавлять сетевую задержку к каждому запросу.

## Запуск

Требуется Node.js 24. Создайте бота у [BotFather](https://t.me/BotFather) командой `/newbot`. Каждый участник должен самостоятельно открыть бота и нажать Start, чтобы бот мог писать ему в личку.

1. Создайте базу PostgreSQL в [Neon](https://neon.com). Скопируйте pooled connection string с включённым TLS (`sslmode=require`).
2. Установите зависимости и создайте локальный файл настроек:

   ```sh
   npm ci
   cp .env.example .env
   ```

3. Заполните `.env`:

   | Переменная | Значение |
   | --- | --- |
   | `BOT_TOKEN` | Токен от BotFather |
   | `DATABASE_URL` | Строка подключения Neon с TLS; вместо неё поддерживается `DATABASE_POSTGRES_URL` от интеграции Vercel с префиксом `DATABASE` |
   | `ADMIN_TELEGRAM_IDS` | Ваш числовой Telegram ID; несколько ID через запятую |
   | `WEBHOOK_SECRET` | Независимый случайный секрет, минимум 32 символа; буквы, цифры, `_`, `-` |
   | `CRON_SECRET` | Другой случайный секрет, минимум 32 символа |
   | `APP_URL` | Production-адрес проекта Vercel, например `https://example.vercel.app` |

   Чтобы получить случайный секрет, выполните отдельно для каждого секрета:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

   Если Telegram ID пока неизвестен, можно временно оставить `ADMIN_TELEGRAM_IDS` пустым, запустить бота локально и отправить `/id`. Затем внесите ID и перезапустите бота. Значение не даёт доступ чужим группам: оно разрешает создать собственную.

4. Создайте таблицы и проверьте проект:

   ```sh
   npm run migrate
   npm run check
   npm test
   ```

5. Для локального запуска используйте `npm run dev`. Локальный режим получает сообщения через long polling; если webhook уже подключён, запуск остановится с подсказкой. Для разработки рекомендуется отдельный бот и отдельная база.

Не добавляйте заполненный `.env` в GitHub. В репозитории хранится только пустой `.env.example`.

## Несколько ботов в одном проекте

Без `BOTS_JSON` работает прежняя конфигурация: `BOT_TOKEN`, `WEBHOOK_SECRET`, `ADMIN_TELEGRAM_IDS`. Ей соответствует внутренний идентификатор `default`; данные из предыдущих версий миграция сохраняет именно за ним.

Чтобы добавить, например, отдельного бота для рабочих задач:

1. Создайте ещё одного бота через BotFather.
2. Добавьте в локальные настройки и Production Vercel `WORK_BOT_TOKEN` и отдельный случайный `WORK_WEBHOOK_SECRET`. Общие `DATABASE_URL` (либо `DATABASE_POSTGRES_URL`), `APP_URL` и `CRON_SECRET` остаются одними на проект.
3. Добавьте переменную **`BOTS_JSON`**, значение — JSON-массив:

   ```json
   [
     {"id":"default","name":"Уборка","tokenEnv":"BOT_TOKEN","webhookSecretEnv":"WEBHOOK_SECRET"},
     {"id":"work","name":"Рабочие задачи","tokenEnv":"WORK_BOT_TOKEN","webhookSecretEnv":"WORK_WEBHOOK_SECRET","adminIds":["123456789"]}
   ]
   ```

   Замените пример ID администратора своим. Поле `adminIds` необязательно: без него используются общие `ADMIN_TELEGRAM_IDS`. В Vercel вставляйте сам JSON без внешних кавычек; в локальном `.env` оберните весь однострочный JSON в одинарные кавычки, как в `.env.example`.
4. Выполните `npm run migrate` перед обновлением приложения. После деплоя запустите `npm run webhook` — скрипт настроит все перечисленные боты.
5. Откройте каждого бота и отдельно создайте группу через `/create Название`. Код приглашения работает только у выдавшего его бота. Участники должны нажать Start в каждом боте, которым пользуются.

`tokenEnv` и `webhookSecretEnv` содержат **названия** переменных окружения, а не секретные значения. `name` — название в конфигурации и реестре; видимое имя Telegram задаётся через BotFather. Каждый бот требует собственные токен и webhook-секрет. Поддерживается до 20 ботов в конфигурации; обработка и доставка рассчитаны на небольшие группы.

Идентификатор `id` — постоянный ключ данных: используйте `default` для существующего бота и новые ключи вроде `work`, `shopping` для новых. Не меняйте ID после начала работы. Замена токена после перевыпуска в BotFather допускается для того же Telegram-бота; попытка привязать этот ID к другому Telegram-боту отклоняется. Удаление бота из конфигурации останавливает его обработку и доставку, сохраняя данные в базе.

Адреса webhook различаются параметром: `/api/webhook?bot=default`, `/api/webhook?bot=work`. Старый адрес `/api/webhook` продолжает обслуживать только `default`. Чужой webhook-секрет не подходит даже при подмене параметра. Ежедневный Cron обслуживает всех настроенных ботов; сбой одного бота не останавливает обработку остальных.

## Деплой на Vercel

1. Импортируйте этот GitHub-репозиторий в [Vercel](https://vercel.com/new). Framework — Other, корень — корень репозитория. Настройки сборки и папки `public` уже указаны в `vercel.json`.
2. Добавьте настройки из `.env.example` в окружение **Production** проекта. Для preview используйте отдельные токен и базу либо не подключайте preview к Telegram.
3. Выполните миграцию из локального проекта против production-базы командой `npm run migrate`, затем выполните деплой.
4. Укажите итоговый production-адрес в локальном `APP_URL` и выполните `npm run webhook`. Скрипт зарегистрирует защищённые webhook и команды меню для всех настроенных ботов. Не открывайте URL с токеном бота в браузере.
5. Production webhook должен быть доступен Telegram без Vercel Authentication / защиты паролем. Сам обработчик проверяет секрет Telegram. Cron проверяет `Authorization: Bearer CRON_SECRET`.
6. Отправьте боту `/create Наша группа`, затем передайте код участникам. Откройте `/new` для первой задачи и `/group` для личных имён.

Cron запускается только на production-деплое. Постоянно работающий сервер не нужен. Подробности: [Vercel Cron](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing), [grammY на Vercel](https://grammy.dev/hosting/vercel), [Neon и Node.js](https://neon.com/docs/guides/node), [Telegram Bot API](https://core.telegram.org/bots/api).

## Проверки

`npm test` использует встроенный PostgreSQL через PGlite и не обращается к Telegram. Проверяются личные имена, изоляция групп, приглашения, сценарии кнопок, периодичность, отмена выполнения, передача только одному помощнику, повторная доставка обновлений и очередь уведомлений.

Для проверки с настоящим PostgreSQL задайте `TEST_DATABASE_URL` на **пустую тестовую базу**. Тесты очищают её таблицы перед каждым сценарием. GitHub Actions автоматически поднимает PostgreSQL 17 и запускает эти же тесты, включая одновременное принятие просьбы через разные соединения.

## Хранение и доставка

Схема создаётся последовательными миграциями из `migrations/`. Применённые файлы учитываются в `schema_migrations`. Перед обновлением выполните `npm run migrate`: `002_groups.sql` переименует прежние таблицу и поля с сохранением данных, `003_coalesced_occurrences.sql` добавит ограничение «одна открытая задача» для выбранного режима, `004_multiple_bots.sql` перенесёт прежние данные под бота `default` и разделит ключи пользователей, диалогов, событий Telegram и очереди по ботам. Токены в базе не хранятся. Исторические миграции сохранены для совместимости.

Действие, журнал и очередь исходящих сообщений записываются одной транзакцией. Повтор Telegram update не выполняет действие второй раз; ID обновлений хранятся 30 дней отдельно для каждого бота. Состояние диалогов хранится в PostgreSQL и истекает через час. Принятие помощи блокирует шаблон и строку текущей задачи, поэтому два получателя не могут оба забрать её.

Сообщения отправляются после фиксации транзакции. При временной ошибке они остаются в `outbox`, получают задержку перед повтором и повторяются при следующем обращении к боту или ежедневном Cron; в локальном режиме повтор проверяется каждые 15 секунд. Ошибки доступа, блокировка бота и исчерпание 8 попыток переводят сообщение в `dead`. На неактивном боте повтор после временного сбоя может ждать следующего ежедневного Cron. За один запуск отправляется до 25 сообщений, с ограничением времени обработки; MVP рассчитан на небольшую группу.

Telegram не поддерживает ключ идемпотентности для отправки сообщения: при сбое между отправкой и подтверждением в базе возможен повтор текста уведомления. Сама передача задачи и журнал при этом не дублируются. Для проверки недоставленных сообщений:

```sql
SELECT bot_id, id, method, state, attempts, available_at
FROM outbox WHERE state <> 'sent' ORDER BY id;
```

В первую версию не входят удаление участников, смена администратора, редактирование/архивирование созданных шаблонов задач и отдельный веб-интерфейс.

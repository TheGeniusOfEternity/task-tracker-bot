# Task Tracker Bot

Семейный Telegram-бот для домашних задач. TypeScript, grammY, PostgreSQL / Neon и Vercel Functions. Все взаимодействия происходят в личных сообщениях с ботом.

## Что умеет MVP

- Администратор создаёт семью и выдаёт код приглашения. Код действует 7 дней; новый код отменяет предыдущий.
- Участники открывают бота и вступают через `/join КОД`. Один пользователь состоит в одной семье.
- «Семья» показывает участников, их открытые задачи и кнопку «Назвать для себя». Например, «Елена Иванова» → «Мама». Личные имена видны только тому, кто их настроил. Можно вернуть имя из Telegram.
- Администратор создаёт разовые, ежедневные, еженедельные и ежемесячные задачи с постоянным исполнителем.
- Исполнитель отмечает выполнение inline-кнопкой и может отменить свою отметку.
- Исполнитель просит помощи у одного или нескольких участников. Первый согласившийся получает текущее повторение задачи целиком; просьба для остальных закрывается. Будущие повторения остаются у постоянного исполнителя.
- Личные ежедневные напоминания о задачах на сегодня и просроченных; журнал событий за последние 7 дней, до 20 записей.

Бот не получает адресную книгу Telegram. Личные имена задаются вручную через список семьи. Любой участник семьи может просматривать задачи других; завершать задачу может только её текущий исполнитель.

## Правила расписания

Часовой пояс первой версии — `Europe/Moscow`. Срок задачи — конец указанного дня. Можно выбрать дни недели (1 — понедельник, 7 — воскресенье); для ежемесячной задачи используется число даты начала, а в коротком месяце — его последний день. Пропущенные повторения остаются просроченными. На ближайшие 7 дней повторения создаются заранее, остальные появляются при ежедневном запуске или просмотре списка.

Напоминания настроены на 16:00 UTC, то есть в интервале 19:00–20:00 по Москве на Vercel Hobby. Точная минута не гарантируется. Для изменения времени обновите `crons` в `vercel.json` и выполните повторный деплой.

## Запуск

Требуется Node.js 24. Создайте бота у [BotFather](https://t.me/BotFather) командой `/newbot`. Каждый участник должен самостоятельно открыть бота и нажать Start, чтобы бот мог писать ему в личку.

1. Создайте базу PostgreSQL в [Neon](https://neon.com). Скопируйте pooled connection string с включённым TLS (`sslmode=require`).
2. Установите зависимости и создайте локальный файл настроек:

   ```sh
   npm ci
   cp .env.example .env
   ```

3. Заполните `.env`:

   | Переменная | Значение |
   | --- | --- |
   | `BOT_TOKEN` | Токен от BotFather |
   | `DATABASE_URL` | Строка подключения Neon с TLS |
   | `ADMIN_TELEGRAM_IDS` | Ваш числовой Telegram ID; несколько ID через запятую |
   | `WEBHOOK_SECRET` | Независимый случайный секрет, минимум 32 символа; буквы, цифры, `_`, `-` |
   | `CRON_SECRET` | Другой случайный секрет, минимум 32 символа |
   | `APP_URL` | Production-адрес проекта Vercel, например `https://example.vercel.app` |

   Чтобы получить случайный секрет, выполните отдельно для каждого секрета:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

   Если Telegram ID пока неизвестен, можно временно оставить `ADMIN_TELEGRAM_IDS` пустым, запустить бота локально и отправить `/id`. Затем внесите ID и перезапустите бота. Значение не даёт доступ чужим семьям: оно разрешает создать собственную.

4. Создайте таблицы и проверьте проект:

   ```sh
   npm run migrate
   npm run check
   npm test
   ```

5. Для локального запуска используйте `npm run dev`. Локальный режим получает сообщения через long polling; если webhook уже подключён, запуск остановится с подсказкой. Для разработки рекомендуется отдельный бот и отдельная база.

Не добавляйте заполненный `.env` в GitHub. В репозитории хранится только пустой `.env.example`.

## Деплой на Vercel

1. Импортируйте этот GitHub-репозиторий в [Vercel](https://vercel.com/new). Framework — Other, корень — корень репозитория. Настройки сборки и папки `public` уже указаны в `vercel.json`.
2. Добавьте настройки из `.env.example` в окружение **Production** проекта. Для preview используйте отдельные токен и базу либо не подключайте preview к Telegram.
3. Выполните миграцию из локального проекта против production-базы командой `npm run migrate`, затем выполните деплой.
4. Укажите итоговый production-адрес в локальном `APP_URL` и выполните `npm run webhook`. Скрипт зарегистрирует защищённый webhook и команды меню. Не открывайте URL с токеном бота в браузере.
5. Production webhook должен быть доступен Telegram без Vercel Authentication / защиты паролем. Сам обработчик проверяет секрет Telegram. Cron проверяет `Authorization: Bearer CRON_SECRET`.
6. Отправьте боту `/create Наша семья`, затем передайте код участникам. Откройте `/new` для первой задачи и `/family` для личных имён.

Cron запускается только на production-деплое. Постоянно работающий сервер не нужен. Подробности: [Vercel Cron](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing), [grammY на Vercel](https://grammy.dev/hosting/vercel), [Neon и Node.js](https://neon.com/docs/guides/node), [Telegram Bot API](https://core.telegram.org/bots/api).

## Проверки

`npm test` использует встроенный PostgreSQL через PGlite и не обращается к Telegram. Проверяются личные имена, изоляция семей, приглашения, сценарии кнопок, периодичность, отмена выполнения, передача только одному помощнику, повторная доставка обновлений и очередь уведомлений.

Для проверки с настоящим PostgreSQL задайте `TEST_DATABASE_URL` на **пустую тестовую базу**. Тесты очищают её таблицы перед каждым сценарием. GitHub Actions автоматически поднимает PostgreSQL 17 и запускает эти же тесты, включая одновременное принятие просьбы через разные соединения.

## Хранение и доставка

Таблицы создаются миграцией `migrations/001_init.sql`. Действие, журнал и очередь исходящих сообщений записываются одной транзакцией. Повтор Telegram update не выполняет действие второй раз; ID обновлений хранятся 30 дней. Состояние диалогов хранится в PostgreSQL и истекает через час. Принятие помощи блокирует строку текущей задачи, поэтому два получателя не могут оба забрать её.

Сообщения отправляются после фиксации транзакции. При временной ошибке они остаются в `outbox`, получают задержку перед повтором и повторяются при следующем обращении к боту или ежедневном Cron; в локальном режиме повтор проверяется каждые 15 секунд. Ошибки доступа, блокировка бота и исчерпание 8 попыток переводят сообщение в `dead`. На неактивном боте повтор после временного сбоя может ждать следующего ежедневного Cron. За один запуск отправляется до 25 сообщений, с ограничением времени обработки; MVP рассчитан на небольшую семью.

Telegram не поддерживает ключ идемпотентности для отправки сообщения: при сбое между отправкой и подтверждением в базе возможен повтор текста уведомления. Сама передача задачи и журнал при этом не дублируются. Для проверки недоставленных сообщений:

```sql
SELECT id, method, state, attempts, available_at
FROM outbox WHERE state <> 'sent' ORDER BY id;
```

В первую версию не входят удаление участников, смена администратора, редактирование/архивирование созданных шаблонов задач и отдельный веб-интерфейс.
